# DT Mapping India

This repository is a small, runnable companion to the article on large JVM grids and file-backed memory. It compares a heap `long[][]`, one `MappedByteBuffer`, multiple mapped regions, and the Java Foreign Function & Memory API (`MemorySegment`). It is a teaching demo, not a production storage library or a performance benchmark.

## Requirements

- JDK 25. The Gradle build uses a Java 25 toolchain.
- No separate Gradle installation is needed; use the checked-in wrapper.
- The normal demos use small temporary files. `runRegionMapped` writes a temporary 2 MiB file and removes it when finished.

Check the Java runtime with `java -version`. On Windows, run commands from PowerShell:

```powershell
.\gradlew.bat test
.\gradlew.bat bootRun
```

On macOS or Linux, use `./gradlew` with the same task names.

## Demo tasks

| Task | Scenario | Expected result |
| --- | --- | --- |
| `runNaive` | 10,000 × 10,000 primitive cells with `-Xmx256m` | The heap allocation runs out of memory; the demo catches and reports the expected `OutOfMemoryError`. |
| `runSingleBuffer` | A 20,000 × 20,000 grid (3.2 GB) | Reports the `MappedByteBuffer` size limit before creating or mapping a large file. |
| `runRegionMapped` | A 512 × 512 grid in two 1 MiB regions | Reads and writes cells across a region boundary using a small temporary file. |
| `runPanama` | A 1,000 × 1,000 grid | Reads and writes cells through one `MemorySegment` mapping. |

Run an individual task, for example:

```powershell
.\gradlew.bat runRegionMapped
```

The default `bootRun` executes all four examples with a 1,000 × 1,000 grid. The examples touch only a few cells and report a heap snapshot; they do not measure throughput, GC behavior, or page-fault performance. The GC figures in the article are historical workload measurements and are not generated by these demos.

## Reusable grid API

The grid implementations share the `LongGrid` interface: `rows()`, `cols()`, `readCell(row, col)`, `writeCell(row, col, value)`, and `close()`. Dimensions must be positive, byte-size arithmetic is checked, and row and column bounds are validated independently. Invalid coordinates throw `IndexOutOfBoundsException` rather than aliasing a cell in a neighboring row.

- `NaiveHeapGrid` stores primitive `long` values in a two-dimensional heap array. Its `close()` is a no-op.
- `SingleBufferGrid` maps one file region and rejects grids larger than `Integer.MAX_VALUE` bytes before mapping. Use it only when the complete grid fits that limit.
- `RegionMappedGrid` splits the file into long-aligned regions no larger than `Integer.MAX_VALUE` bytes. Its default region size is 1 GiB; an alternate region size can be supplied for bounded workloads and tests.
- `PanamaGrid` uses the finalized Foreign Function & Memory API and owns a confined arena. Use and close each instance on the creating thread.

Mapped grids own and release their mappings when closed; reads and writes after close fail with `IllegalStateException`, and repeated close calls are safe. The supplied `FileChannel` remains caller-owned. Mappings use native byte order and map a fixed row-major layout of eight bytes per cell; the caller is responsible for choosing, retaining, and managing the backing file. Closing a mapping releases its resources, but applications that require explicit durability/checkpoint guarantees should define and test their own flush protocol.

The demos create uniquely named temporary mapping files beside the configured `grid.file` path (default `grid.dat`) and remove only the temporary files they created. A forced process termination can leave a temporary file behind; existing files are not opened or deleted by the demos.

The legacy `MappedByteBuffer` demos use `Unsafe.invokeCleaner` through `BufferCleaner` for deterministic unmapping. This is an internal JDK API enabled by Gradle module-opening arguments and is not a portable production contract. The Panama example does not need those opens.

## Configuration

Spring command-line properties can override the default grid and selected demo:

```powershell
.\gradlew.bat bootRun --args="--demo.step=region-mapped --grid.rows=512 --grid.cols=512 --grid.region-bytes=1048576"
```

Valid `demo.step` values are `all`, `naive`, `single-buffer`, `region-mapped`, and `panama`. `grid.region-bytes` must be positive, no larger than `Integer.MAX_VALUE`, and divisible by eight.
